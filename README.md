# Zenith Landing | 광고 랜딩 운영 모듈

광고·이벤트 랜딩 페이지를 여러 도메인에서 운영하고, 방문자의 신청 정보를 검증·저장한 뒤 조건에 따라 외부 제휴 시스템으로 전달하는 PHP 기반 실행 모듈입니다.

제니스 백오피스가 광고주, 이벤트와 전송 정책을 관리한다면 이 저장소는 실제 유입 요청을 처리하는 역할을 담당합니다.

> 공개 저장소에는 핵심 처리 파일만 포함되어 있습니다. 이벤트별 랜딩 자산, 운영 DB 연결 코드, 실제 제휴 설정과 개인정보는 제외했습니다.

## 개발 배경과 역할

광고 캠페인마다 별도의 랜딩 페이지와 신청 양식을 운영하면서도 데이터 저장, 중복 검사, 차단 정책과 제휴 전송은 같은 기준으로 처리해야 했습니다. 개별 랜딩마다 처리 로직을 중복 구현하면 정책 변경 시 수정 범위가 커지고, 실패 건을 다시 보내거나 처리 상태를 추적하기도 어려워집니다.

공통 실행 모듈이 이벤트 설정을 읽어 랜딩을 조합하고 신청 요청을 검증하도록 구성했습니다. 정상·중복·조건 불일치·테스트 데이터 등의 상태를 분류하고, 외부 전송 실패 건은 별도 재처리할 수 있도록 분리했습니다.

## 요청 처리 흐름

```text
이벤트 URL 또는 해시 URL 접근
              |
              v
     이벤트 정보·랜딩 조회
              |
              v
 PHP 템플릿과 정적 자산 조합
              |
              v
      신청 폼 데이터 수신
              |
              v
필수값·중복·IP·쿠키·블랙리스트 검증
              |
              v
      저장 및 처리 상태 분류
              |
      +-------+--------+
      |                |
      v                v
완료 페이지·Pixel   외부 제휴 전송
                       |
                       v
                실패 기록·재전송
```

## 설계 및 구현

### 1. 이벤트별 랜딩 라우팅

- 이벤트 번호 또는 해시 기반 URL 해석
- DB의 이벤트 설정에 따라 랜딩 템플릿 동적 선택
- 공통 head·tail과 이벤트별 PHP·HTML·CSS·JavaScript 조합
- 처리 결과에 따른 완료 페이지와 오류 페이지 이동

### 2. 신청 데이터 검증과 상태 분류

- JSON과 일반 POST 요청 처리
- 이름, 전화번호, 성별, 나이, 주소와 메모 등 신청값 수집
- 필수값, 연령 조건과 전화번호 형식 검증
- 이름·전화번호·IP·쿠키 기준 중복 요청 확인
- 블랙리스트와 내부 운영 정책에 따른 차단
- 정상, 중복, 조건 불일치, 불량 번호와 테스트 데이터 상태 분류

### 3. 외부 연동과 실패 재처리

- 이벤트별 제휴 전송 스크립트 실행
- cURL 기반 외부 API 요청과 응답 처리
- 제휴사별 성공·실패 응답을 내부 상태로 변환
- 실패 원인과 처리 메모 기록
- 단건 및 조건 기반 일괄 재전송 스크립트 제공

### 4. 개인정보 보호와 방문 상태 관리

- 전화번호 등 개인정보 AES 암복호화
- Sodium 지원 환경을 고려한 키 처리
- 세션과 쿠키 기반 방문자 상태 관리
- 내부·외부 IP 구분과 요청 IP 기록
- 민감한 키를 코드가 아닌 환경변수에서 로드

## 주요 결과

- 캠페인별 랜딩과 공통 신청 처리 로직을 분리해 정책 변경 범위 축소
- 중복·블랙리스트·조건 검사를 공통화해 신청 데이터 분류 기준 통일
- 외부 제휴 전송과 실패 재처리를 분리해 운영자가 누락 건을 다시 처리 가능
- 개인정보 암호화와 IP·쿠키 검증을 적용해 신청 데이터 보호 수준 향상
- 백오피스의 이벤트 설정과 실제 방문 요청 처리를 하나의 운영 흐름으로 연결

## 기술 스택

| 영역 | 기술 |
| --- | --- |
| Backend | PHP, MySQLi |
| HTTP | cURL |
| Security | OpenSSL AES, Sodium, Session, Cookie |
| Frontend | PHP Template, HTML, CSS, JavaScript |
| Environment | Apache/Nginx, MySQL |

## 핵심 파일

| 파일 | 역할 |
| --- | --- |
| `zenith_core.php` | 이벤트 라우팅, 랜딩 렌더링과 완료 페이지 처리 |
| `zenith_check_proc.php` | 신청 검증, 중복 검사, 상태 분류와 저장 후처리 |
| `zenith_interlock.php` | 외부 제휴 전송 결과 처리 |
| `interlock_resend.php` | 실패 건 단건 재전송 |
| `interlock_resend_all.php` | 조건 기반 일괄 재전송 |
| `zenith_encryption.php` | 개인정보 암복호화 |
| `zenith_ip.php` | 방문자 IP 확인과 내부망 구분 |
| `zenith_cookie.php` | 중복 확인용 쿠키 생성과 조회 |
| `zenith_test.php` | 연동 요청 점검 |
| `zenith_test_form.php` | 신청 폼 전송 점검 화면 |

## 원본 운영 구조

```text
zenith-operate/
├── data/                    # 이벤트별 랜딩·완료·제휴 스크립트
├── inc/                     # 공통 head·tail·알림 템플릿
├── error/                   # 오류 화면
├── zenith_db.php            # 운영 DB 연결·쿼리 래퍼
├── zenith_core.php          # 랜딩 실행 진입점
├── zenith_check_proc.php    # 신청 처리
└── zenith_interlock.php     # 외부 제휴 연동
```

현재 공개본에는 `data/`, `inc/`, `error/`와 `zenith_db.php`가 포함되어 있지 않으므로 운영 환경을 그대로 실행할 수 없습니다.

## 실행 환경

- PHP 실행이 가능한 웹 서버
- MySQL 접근 환경과 `mysqli` 확장
- `curl`, `openssl`, `mbstring` 확장
- 가능한 경우 `sodium` 확장
- 세션과 쿠키를 사용할 수 있는 HTTPS 환경

환경변수 예시는 `.env.example`에서 확인할 수 있으며 실제 키는 저장소에 포함하지 않습니다.
